# Spec 模板（项目 Spec / 功能 Spec 通用）

> **使用方式**：每次产出 Spec 时**复制本模板**为 `<project>-spec.md`（项目级）或 `<feature>-spec.md`（功能级），逐字段填写；不适用项写 `N/A` 并简述原因，**严禁删除字段**。
> **依据**：[`.qoder/constitution.md`](../constitution.md) §2.2、§3、§5。

---

## 1. 元信息

| 字段 | 值 |
|------|---|
| Spec 类型 | `项目 Spec` / `功能 Spec` |
| 项目 | 例：life-os |
| Feature 名 | 仅功能 Spec 填写 |
| 治理层级 | T0 / T1 / T2 / T3（依据宪法 §3 判定，无法判定必须升级用户确认） |
| 状态 | 草稿 / 评审中 / 已批准 / 实施中 / 已交付 / 已归档 |
| 维护人 | 用户姓名 |
| 创建 / 最近更新 | YYYY-MM-DD |
| 关联 Plan | `<feature>-plan.md` 路径列表 |
| 关联 Design | `.qoder/specs/<project>-design.md`（涉 UI 必填） |

---

## 2. 目标与边界

- **做什么**：用户故事 / 业务价值 / 一句话描述（功能 Spec 必填）。
- **不做什么**：明确划出本 Spec 不覆盖的范围，避免 scope creep。
- **干系人**：受益方、决策方、复核方。

## 5. 受影响文件列表（白名单）

> 仅列出本 Spec 范围内**允许修改**的文件 / 目录。后续 plan.md 的白名单必须 ⊆ 本表。

- `路径/文件` —— 修改用途简述

## 6. 任务清单

| # | 任务 | 状态 | 负责 | 关联 Plan |

| 1 | 例：建表 user | 待办 / 进行中 / 完成 / 阻塞 | AI / 人 | `xxx-plan.md` |

## 7. 风险与回归点

- 风险 1：描述 + 触发条件 + 缓解方案
- 回归点：本 Spec 落地可能影响的其他模块 / Spec / Plan
- 平行 Feature 耦合：与哪些 Spec 共享模型 / 服务，需在哪些文档同步登记
